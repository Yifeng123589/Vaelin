# 设计叙事（脱敏）

> 来源改写：公开设计札记＋产品界面设想。已去本机路径、私人昵称、未公开实验 ID。  
> 用途：说明「为什么要做主动式陪伴、边界在哪里」。

## 1. 动机：陪伴，而不是「赛博恋人」

市场上不难见到把大模型包成「会说我爱你」的虚拟形象。开发者圈子常觉得那「很蠢」——API 应用在工程与科研上更「正经」。但爆款 AI 往往靠的是一点点惊喜感，而不只是编码或算法展示。

设计立场：

- **不认可**把 AI 做成感情伴侣（把过多情感押在虚拟形象上，可能对现实社交造成不可逆影响）。
- **认可**做成**陪伴者**：可以主动说话，同时处处有边界。
- 目标不是替代人际关系，而是探索「主动关心」在频率与安全上如何同时成立。

一句话：又想主动说话，又处处设置边界——希望它是答案之一，而不是唯一答案。

## 2. 产品壳设想（远景 · 非本包交付）

聊天入口偏即时通讯式；设置侧参考常见 agent 产品。状态栏可切换三种模式（命名为产品远景代号，非生产配置）：

| 模式 | 意图 |
|---|---|
| 氧气（Oxygen） | 「呼吸活人感」——对应主动式陪伴 |
| 凯撒（Caesar） | 关系网视图（网状节点；节点可开小窗对话或侧栏对话） |
| 玥 | 外接扩展面（例如把独立测评模组以打包形式挂入） |

另有「反思」流水设想：多轮调用——先全工具生成并收尾 → 再无工具只审日志／产物逻辑 → 再在子代理侧把有用记忆写入（自进化）并收尾。此为产品／工程远景，不构成本包运行说明。

## 3. 硬边界（与知情说明一致）

- 研究原型，**不是**医疗产品；不构成诊断或治疗建议。  
- 危机相关信号时：安全话术＋求助资源；不联系第三方、不自动报警、不假装专业人士。  
- 安全护栏与危机处置链**不向终端用户提供关闭开关**（见知情说明）。  
- 真实困扰请寻求专业帮助。
